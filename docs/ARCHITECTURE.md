# Oxblend architecture

The reader checks header/BHead grammar, decoded extents and SDNA before exposing reflected fields. Raw inputs use checked read-at backing. Default trace/list keep the fast invocation-owned decoded RAM snapshot. Opt-in `trace --low-memory` / `list --low-memory` inspect seekable zstd lazily. On first touch each frame is streamed once into a private unnamed spill; unqueried whole frames are skipped. A header-only physical framing walk independently compares every compressed extent before trusting the table. Zero decoded data-frame claims are verified by actual decode (they cannot hide bytes); touched-frame decoded length must exactly match its claim. Whole-frame-on-touch avoids repeated prefix decoding on backwards graph visits, with one active decoder and no decoded frame retained in RAM. Blocks stays streaming/uncached without spill or retained decoded frames. A partial read does not certify full-source checksums. In low-memory mode gzip/non-seekable zstd, and damaged or contradictory optional seek indexes, use checked full-stream decoding into a private unnamed spill and the same read-at parser. Full-frame kept-closure/write proofs remain separate and unchanged.

Seek-table fallback always emits its one structured JSON warning at the transition, before checked recovery (even if recovery fails). Set `FLATTRACE_DIR` for flattrace reader statistics, including source mode. Blocks has no new stderr diagnostic output. Decode work, spill bytes written, verified and skipped frames are reported separately. Default stdout is unchanged. The equivalent API control is `TraceOptions.low_memory` (default `false`). Choose low-memory mode for memory pressure, not speed; the default remains speed-first.

Each file owns its pointer index. ID namespaces and contiguous owner-DATA runs are distinct; duplicate addresses do not become last-wins. Read profiles, diagnostic census and strict graph/write admission are separate contracts. Diagnostics deliberately avoid claims that lack a qualified saved-layout role.

Trace lists dependencies, not append-origin `library_weak_reference` metadata. A selected local override's `ID.override_library.reference` is a real loading edge: the native loader still loads the original ID and its dependencies after local overrides remove edges. Both trace and list follow that exact reference through the normal qualified ID/stub walk; pack uses this closure. Text path ownership comes from saved TXT_ISMEM, independently of dirty state or cached lines: embedded historical locations are informational records only, while external Texts remain dependencies. Merely adding its physical Library filename would miss nested source libraries, while censusing unrelated Library headers would overreach. Trace is an invocation-owned asset walk with byte-safe identities, explicit provenance and final source guards. Pack captures inputs, validates the dependency plan and guarded rewrites, then publishes completed files or one ZIP. Compressed inputs stream directly from a checked source descriptor into one immutable decoded snapshot; no full encoded buffer exists even during decoding. Raw blend capture is already the decoded data. Opaque asset prefetch streams through the existing read buffer and retains only metadata and an XXH64 identity digest, not body bytes. Publication streams the asset into its private stage while hashing the exact copied bytes and comparing the captured digest. Ctime-inclusive signatures and physical length are checked before/after copying; completed opaque captures retain proof only. Opaque-asset memory therefore does not grow with asset byte size (parsed blend snapshots remain invocation-owned). A same-pass immutable frame/table verdict binds source device/inode/size/mtime/ctime (including nanoseconds); physical admission borrows the owning immutable snapshot, so a different decoded backing cannot be substituted. Write admission reuses that verdict and preserves malformed-table error kind, message and phase. No live descriptor is retained per snapshot. Physical no-op/parsed-asset copies reopen the guarded source and use Linux `copy_file_range`, looping on every positive return. First-call zero, `EXDEV`, `ENOSYS` or `EOPNOTSUPP` before any progress permit a buffered user-space fallback: compressed inputs stream from the FD, raw inputs write their already captured physical bytes without rereading. Zero after progress and all other or after-progress errors refuse. Signature and length checks surround transport, and a final source check follows output verification immediately before publication. Editing uses expected-old guards and destination-owned exclusive staging with atomic no-replace publication. No background daemon, persistent cache or global pointer map is required.

Linked-library compatibility has one narrow owner (`library_compat`): it proves
observed nullable ID slots, source-SDNA extents and native callers before treating
an absent lib-map entry as a warning. It never substitutes for structural/DATA
resolution. Pack reuses the same proof for expected-old NULL clears across copied
libraries, merging those spans with path spans in the existing checked emitter.
It reports the repair plan separately from path edits. Main-file admission and
all other graph/write refusals remain strict; Blender, not Oxblend, reconstructs
the qualified legacy realization node groups and reapplies library overrides
on open.

Local diagnostics use the vendored MIT flattrace v1 writer. The CLI owns a
process writer with exclusive access; worker spans capture the long-lived command
parent, not short-lived planning scopes. File open, index/schema, command,
pack plan/copy/repath, staged write and no-replace publication are separate spans.
`reader.stats` retains source-mode/decode/spill/frame counters; `copy.stats`
retains bytes, mechanism and fallback errno/reason. These facts do not certify
publication. No ends are invented on exit or kill. See [USAGE](USAGE.md#local-flattrace-diagnostics).

Serialized override inspection reports saved records and reference chains; it never evaluates or applies overrides. Source signatures detect changes, but do not constitute an atomic filesystem snapshot. Write signatures additionally bind ctime; a same-size rewrite restoring mtime within one filesystem timestamp tick of capture is not detectable when ctime also remains unchanged. Read-only trace/list/blocks use their five-field checks. See [source-change detection](USAGE.md#source-change-detection).
