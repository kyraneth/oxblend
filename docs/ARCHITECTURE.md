# Oxblend architecture

The reader checks header/BHead grammar, decoded extents and SDNA before exposing reflected fields. Raw inputs use checked read-at backing. Default trace/list keep the fast invocation-owned decoded RAM snapshot. Opt-in `trace --low-memory` / `list --low-memory` inspect seekable zstd lazily. On first touch each frame is streamed once into a private unnamed spill; unqueried whole frames are skipped. A header-only physical framing walk independently compares every compressed extent before trusting the table. Zero decoded data-frame claims are verified by actual decode (they cannot hide bytes); touched-frame decoded length must exactly match its claim. Whole-frame-on-touch avoids repeated prefix decoding on backwards graph visits, with one active decoder and no decoded frame retained in RAM. Blocks stays streaming/uncached without spill or retained decoded frames. A partial read does not certify full-source checksums. In low-memory mode gzip/non-seekable zstd, and damaged or contradictory optional seek indexes, use checked full-stream decoding into a private unnamed spill and the same read-at parser. Full-frame kept-closure/write proofs remain separate and unchanged.

Seek-table fallback always emits its one structured JSON warning at the transition, before checked recovery (even if recovery fails). Set `OXBLEND_READ_REPORT=1` for trace/list source-mode/statistics JSON on stderr (`OXBLEND_READ`). Blocks has no new diagnostic output. Decode work, spill bytes written, verified and skipped frames are reported separately. Default stdout is unchanged. The equivalent API control is `TraceOptions.low_memory` (default `false`). Choose low-memory mode for memory pressure, not speed; the default remains speed-first.

Each file owns its pointer index. ID namespaces and contiguous owner-DATA runs are distinct; duplicate addresses do not become last-wins. Read profiles, diagnostic census and strict graph/write admission are separate contracts. Diagnostics deliberately avoid claims that lack a qualified saved-layout role.

Trace lists dependencies, not append-origin `library_weak_reference` metadata. Trace is an invocation-owned asset walk with byte-safe identities, explicit provenance and final source guards. Pack captures inputs, validates the dependency plan and guarded rewrites, then publishes completed files or one ZIP. Compressed inputs stream directly from a checked source descriptor into one immutable decoded snapshot; no full encoded buffer exists even during decoding. Raw capture is already the decoded data; opaque assets retain their captured bytes. A same-pass immutable frame/table verdict binds source device/inode/size/mtime/ctime (including nanoseconds); physical admission borrows the owning immutable snapshot, so a different decoded backing cannot be substituted. Write admission reuses that verdict and preserves malformed-table error kind, message and phase. No live descriptor is retained per snapshot. Physical no-op/parsed-asset copies reopen the guarded source and use Linux `copy_file_range`, looping on every positive return. First-call zero, `EXDEV`, `ENOSYS` or `EOPNOTSUPP` before any progress permit a buffered user-space fallback: compressed inputs stream from the FD, raw inputs write their already captured physical bytes without rereading. Zero after progress and all other or after-progress errors refuse. Signature and length checks surround transport, and a final source check follows output verification immediately before publication. Editing uses expected-old guards and destination-owned exclusive staging with atomic no-replace publication. No background daemon, persistent cache or global pointer map is required.

With `OXBLEND_READ_REPORT=1`, successful physical transports emit one `OXBLEND_COPY ` line followed by compact JSON on stderr (stdout remains the normal report). Exact line templates below substitute `<path_hex>` with lowercase source-path byte hex; every line ends with a newline:

```text
OXBLEND_COPY {"fallback_errno":null,"fallback_reason":null,"mechanism":"copy_file_range","path_hex":"<path_hex>"}
OXBLEND_COPY {"fallback_errno":18,"fallback_reason":"errno","mechanism":"streamed","path_hex":"<path_hex>"}
OXBLEND_COPY {"fallback_errno":38,"fallback_reason":"errno","mechanism":"streamed","path_hex":"<path_hex>"}
OXBLEND_COPY {"fallback_errno":95,"fallback_reason":"errno","mechanism":"streamed","path_hex":"<path_hex>"}
OXBLEND_COPY {"fallback_errno":null,"fallback_reason":"zero_return","mechanism":"streamed","path_hex":"<path_hex>"}
```

Errnos above are Linux `EXDEV`, `ENOSYS`, `EOPNOTSUPP` respectively. A transport diagnostic is not a publication-success verdict: a later source guard can still refuse. Default stdout/stderr and blocks diagnostics are unaffected.

Serialized override inspection reports saved records and reference chains; it never evaluates or applies overrides. Source signatures detect changes, but do not constitute an atomic filesystem snapshot. Write signatures additionally bind ctime; a same-size rewrite restoring mtime within one filesystem timestamp tick of capture is not detectable when ctime also remains unchanged. Read-only trace/list/blocks use their five-field checks. See [source-change detection](USAGE.md#source-change-detection).
